# HomeAuction — анонимный аукцион на выбывание

Веб-приложение на **Node.js / Express / Socket.IO** и **Canvas 2D**. Участники анонимно создают лоты и распределяют очки; когда все готовы, ведущий запускает колесо. Сервер определяет победителя **до первого вращения**, визуальные эффекты на выбор не влияют.

## Быстрый запуск

### Windows — одно окно терминала

1. Установите Node.js с `npm` и доступом к интернету для загрузки зависимостей и Cloudflare Tunnel.
2. Распакуйте **весь** ZIP в папку, не перемещая файлы из неё.
3. Запустите **`start.bat`** двойным щелчком. Первый запуск может потребовать времени для `npm ci` и `npx`.
4. В **единственном видимом окне** появится локальная ссылка `http://localhost:3000` и, после успешного подключения Cloudflare, адрес `https://...trycloudflare.com`.
5. **Закройте это окно**, чтобы остановить сервер и туннель. `launch.ps1` использует Windows Job Object с `KILL_ON_JOB_CLOSE`, который завершает дочерние процессы при закрытии консоли, и резервную очистку дерева процессов при штатном завершении.

Технически `start.bat` вызывает `launch.ps1` в этом же окне. Node.js и Cloudflare запускаются **без собственных видимых консолей**, а вывод Cloudflare собирается в логах и считывается управляющим скриптом. Для стандартной Windows 10/11 используйте встроенный Windows PowerShell 5.1+. Если в процессе запуска появляется ошибка, текст останется в основном окне. **Проверку именно в Windows необходимо провести на вашей машине** — здесь тестировался код приложения, а не ОС Windows.

### Linux / macOS

Запустите `./start.sh` (для первого запуска `chmod +x start.sh`). Скрипт устанавливает зависимости при необходимости и запускает сервер с туннелем. На macOS может потребоваться современный Bash, поскольку скрипт использует `wait -n`.

### Вручную

```bash
npm ci
node server.js
```

В другом терминале:

```bash
npx cloudflared tunnel --url http://localhost:3000
```

Требуется открытый порт 3000 на локальной машине. Временный адрес Cloudflare меняется при новом запуске туннеля.

## Игровые правила

- Первый вошедший становится **ведущим**. Логика комнаты и разрешения проверяются на сервере.
- **N** (`maxPoints`, по умолчанию 100) — общий бюджет каждого игрока; **maxItems** (по умолчанию 3) — количество добавляемых им лотов.
- **Распределение без ограничений — по умолчанию**: все N очков можно отдать своим лотам, чужим или разделить между ними. Правила доступны в отдельных карточках баланса на этапе пула.
- Дополнительная опция ведущего **«Ограничить ставки на свои варианты»** задаёт резерв **R** (`foreignOnlyPoints`) в диапазоне 0…N. Тогда максимум **N − R** очков разрешено поставить суммарно на *свои* лоты, а **R** очков зарезервированы исключительно для лотов *других* игроков. При этом на чужие варианты по-прежнему разрешено потратить **все N**, если хочется. Резерв не требуется тратить обязательно.
- Пример: N = 100, R = 40 → не более 60 очков на свои варианты, до 100 на чужие, суммарно максимум 100.
- При изменении правил сервер уменьшает избыточные ставки на собственные варианты, возвращает очки на баланс и снимает готовность с затронутых игроков.
- Ползунки ставок имеют **фиксированную шкалу 0…N**, поэтому изменение ставки на одном варианте не изменяет положение ползунков остальных вариантов. Сервер изменяет только ставку указанного лота и ограничивает её общим остатком и правилами для своих лотов.
- На стадии тайного пула другим игрокам **не раскрываются** ваши суммы по лотам. После нажатия «Готов» всеми участниками пул открывается целиком.
- При желании ведущий оставляет на колесе варианты с 0 очков, тогда им присваивается настроенный ненулевой базовый вес; иначе такие лоты не попадают на колесо.
- До первого вращения ведущий может объединить дублирующиеся лоты — очки суммируются.

## Управление колесом

- **Большой режим включён по умолчанию**. На широком экране *таблица вероятностей, список «Варианты на колесе» и история выбывания всегда находятся справа от колеса*, в том числе при увеличении. На узких экранах панели переносятся вниз для читаемости.
- При наведении на сектор появляется широкая подсказка с полным названием; она удерживается внутри видимой области экрана, без переноса по одному слову/букве. Для очень узких секторов сохраняется список полных названий под колесом.
- **Время прокрутки** вынесено в отдельную панель рядом с колесом. От 2 до 500 секунд, шаг 0,5. Ведущему доступны кнопки −5/+5 и «Применить»; кнопки недоступны во время вращения. В тайном пуле панель не показывается, гости видят только значение.
- **«Авто-крутка»** последовательно удаляет лоты до определения победителя; следующая прокрутка ждёт конца эффекта выбывания.
- Вверху страницы: общая кнопка «Эффекты ВКЛ/ВЫКЛ», отдельные галочки выбора эффектов, мастер-галочка **«Включить все эффекты»**, а также кнопки **«Включить всё» / «Выключить всё»**. Если не выбран ни один эффект или общий переключатель выключен, используется сворачивание дуги (вариант №0).
- Выбор анимации из отмеченных эффектов псевдослучаен для каждого раунда. Галочки — локальная настройка браузера, поэтому у двух зрителей с разными галочками анимации могут отличаться.
- Звуки в браузере синтезируются через Web Audio API и подчиняются общей кнопке звука. При `prefers-reduced-motion` сложная визуализация пропускается.

### Эффекты выбывания

Все эффекты происходят **внутри колеса и на изображении выбывающего сектора**. Всплывающих плашек нет.

| № | Эффект | Поведение |
|---|---|---|
| 0 | Сворачивание | Уменьшается **угол дуги сектора**, а не его ширина слева направо |
| 1 | Стекло | Разрастаются трещины, фрагменты исходного сектора падают и вращаются |
| 2 | Взрыв | Сектор распадается на осколки со вспышкой и искрами |
| 3 | Выстрел | Небольшое неровное пулевое отверстие, кровавое пятно и неодинаковые **вертикальные потёки**, без брызг |
| 4 | Жвачка / пузырь | Дрожание, небольшое расширение, разрыв мембраны, тянущиеся липкие нити и падающие лоскутки |
| 5 | Разрез | **Прямая** наклонная линия, две половины расходятся |
| 6 | Глитч | Горизонтальные цифровые смещения |
| 7 | Пиксельный распад | Отдельные пиксели вылетают и растворяются |
| 8 | Вихрь | Сектор закручивается и исчезает, **без собственных частиц** |
| 9 | Одна трещина | **Радиальная трещина от центра к краю**, верхняя часть съезжает по нижней и падает |

### Сброс

- **Сбросить в пул** — сохраняет названия вариантов, обнуляет ставки и результаты.
- **Очистить лоты и ставки** — оставляет участников и настройки, возвращает к начальной стадии.
- **Полный сброс комнаты** — сбрасывает *всё*, включая участников, правила, очки, историю и текущее вращение. Запущенные Node.js и туннель сохраняются. Пользователи попадают на экран входа; первый заново вошедший становится ведущим.

## Архитектура

```text
                            браузер ведущего / браузеры игроков
                                         │
                              HTTP (UI)  │  WebSocket / Socket.IO
                                         ▼
┌─────────────────────────────────────────────────────────────────────────┐
│                      Node.js: server.js                                │
│   Express: отдаёт ./public          Socket.IO: игровой протокол          │
│                                                                         │
│    state (оперативная память одной комнаты)                              │
│     ├── phase: POOL → REVEAL → FINISHED                                  │
│     ├── settings: очки, ставки, пул, время вращения                      │
│     ├── players: Map(token → игрок)                                      │
│     ├── items: лоты и allocations[token] → число очков                  │
│     └── wheel: фиксированный победитель, раунд, история                  │
│                                                                         │
│    Обработчики join / add_item / set_points / toggle_ready             │
│    update_settings / update_spin_duration / spin_wheel / reset_*        │
└─────────────────────────────────────────────────────────────────────────┘
                        │                        │
               state_update каждому         wheel_spin всем
               (приватное состояние)        (геометрия раунда)
                        ▼                        ▼
            ┌─────────────────────────────────────────────────┐
            │ public/client.js  — DOM, события, Canvas колеса │
            │ public/wheel-effects.js — эффекты сектора       │
            │ public/style.css + index.html — темы и макет   │
            └─────────────────────────────────────────────────┘
```

**Назначение файлов**

| Файл | Ответственность |
|---|---|
| `server.js` | Единый серверный источник истины: проверка прав, ставка, ограничения, выбор победителя, обратные веса, таймеры, сброс |
| `public/client.js` | Socket.IO-клиент, локальные галочки, темы, игровая форма, Canvas, подписи, синхронизация и визуализация вращения |
| `public/wheel-effects.js` | Независимый движок эффектов Canvas 2D, снимок пикселей сектора, осколки, гравитация, кадры `requestAnimationFrame` |
| `public/index.html` | Семантическая разметка экранов, панелей и двухслойного колеса |
| `public/style.css` | Адаптивная сетка, пять тем, шрифты и индикация вероятностей |
| `start.bat` | Точка входа в Windows-режиме с одним терминалом |
| `launch.ps1` | Скрытый запуск и мониторинг дочерних процессов, распознавание временного HTTPS-адреса, управление жизненным циклом через Job Object |
| `start.sh` | Запуск для Unix-подобных систем |
| `package.json`, `package-lock.json` | Зависимости и команды npm |

**Поток данных и математическая модель**

1. `join` создаёт/восстанавливает участника по токену из `localStorage` браузера; первый игрок получает роль ведущего.
2. На `POOL` клиент отправляет `add_item` и `set_points`; сервер проверяет авторство лота, общие N очков и резерв R. Другим игрокам отдаётся состояние без их тайных распределений через `buildClientState(token)`.
3. `toggle_ready` ведёт к `REVEAL` только после готовности всех игроков и наличия хотя бы одного активного лота.
4. При **первом** `spin_wheel` победитель выбирается **один раз** с вероятностью `Sᵢ / ∑ Sⱼ` (где `Sᵢ` — эффективные очки лота). Выбор хранится на сервере.
5. Каждый раунд случайно исключает **не победителя** с весом `1 / Sᵢ`. Относительные углы всех секторов также вычисляются по `1 / Sᵢ`. Сервер сообщает клиентам сегменты, цель стрелки и время.
6. Клиент рисует вращение с замедлением в конце. После остановки изображение удаляемого сектора захватывается в отдельный Canvas и передаётся в `WheelSectorEffects`; никакая анимация не влияет на логику ставок или результат.
7. Серверный таймер отмечает выбывшего и рассылает обновлённое состояние; когда остаётся один лот, наступает `FINISHED`. Полный сброс инвалидирует поколение таймера (`spinGeneration`) и отменяет ожидающий callback.

**Технические ограничения и безопасность**

- Только **одна комната**, состояние хранится **в памяти**: после перезапуска Node.js все игровые данные теряются. Базы данных нет.
- Токены входа — долговременные идентификаторы в `localStorage`, **не аутентификация по паролю**. Не публикуйте ссылку на комнату в открытом доступе: любой обладатель ссылки может войти, а первый вошедший получает права ведущего.
- Сервер проверяет права ведущего для изменения правил, управления колесом и полного сброса; клиентская проверка — только для удобства интерфейса.
- Express отдаёт приложение по HTTP локально; публичный HTTPS-туннель создаёт Cloudflare. Сервер не обеспечивает внешнюю TLS-терминацию самостоятельно.
- Шрифты грузятся с Google Fonts, предусмотрены системные запасные шрифты.

## Проверки и диагностика

- Синтаксис JavaScript: `node --check server.js`, `node --check public/client.js`, `node --check public/wheel-effects.js`.
- При проблемах с BAT проверьте наличие `node`, `npm` и `npx` в `PATH`. Результаты перенаправления stdout/stderr временно записываются в `%TEMP%/HomeAuction_<PID>/` до закрытия скрипта.
- Если временная ссылка Cloudflare не появляется, проверьте интернет, ограничения сети и доступность Cloudflare; приложение по адресу `http://localhost:3000` при этом может работать отдельно.
